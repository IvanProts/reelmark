# Путівник по коду

Як читати проєкт, щоб швидко зрозуміти, що де і чому. Найкраще йти шляхом одного запиту: від
контракту — через API — до екрана застосунку.

## 1. Контракт — з чого все починається

**`packages/shared/src/movies.ts`** — один файл, який описує, як API і застосунок «розмовляють»:

- `DeckQuerySchema` — що застосунок може попросити (`page`, `lang`);
- `DeckResponseSchema` / `MovieCardSchema` — що API зобов'язується повернути;
- `SUPPORTED_LOCALES` — мови, які підтримує проєкт.

Схеми написані на [zod](https://zod.dev): з однієї схеми ми отримуємо і **перевірку даних під час
роботи**, і **TypeScript-тип** (`z.infer`). Тому API і застосунок не можуть «домовитися» по-різному —
розбіжність не скомпілюється.

## 2. API (`apps/api/src`) — шлях одного запиту

Запит `GET /api/v1/movies/deck?page=2&lang=uk` проходить так:

| Крок | Файл                              | Що відбувається                                                                     |
| ---- | --------------------------------- | ----------------------------------------------------------------------------------- |
| 0    | `main.ts`                         | Старт сервера. Якщо `.env` неправильний — сервер не запуститься (і скаже чому).     |
| 1    | `config/env.schema.ts`            | Перевірка змінних середовища (токен, порт, адреса TMDB).                            |
| 2    | `app.setup.ts`                    | Безпекові заголовки (helmet), префікс `/api`, версія `v1`.                          |
| 3    | `app.module.ts`                   | Глобальні «охоронці»: ліміт запитів, валідація, обробник помилок.                   |
| 4    | `movies/movies.controller.ts`     | Приймає запит; `@Query({ schema: DeckQuerySchema })` перевіряє параметри.           |
| 5    | `movies/movies.service.ts`        | Бізнес-логіка: взяти фільми + жанри, за потреби підставити англійські описи.        |
| 6    | `tmdb/tmdb.client.ts`             | **Єдине місце**, що ходить у TMDB: токен у заголовку, тайм-аут, кеш, ліміт розміру. |
| 7    | `tmdb/tmdb.schemas.ts`            | Перевірка відповіді TMDB — чужим даним не довіряємо.                                |
| 8    | `movies/movie-card.mapper.ts`     | Перетворення формату TMDB на наш `MovieCard` (чисті функції, легко тестувати).      |
| ✕    | `common/all-exceptions.filter.ts` | Будь-яка помилка → `{ statusCode, message }` без внутрішніх деталей.                |

Корисні поняття NestJS, які тут видно:

- **Module** (`*.module.ts`) — групує пов'язані класи (контролер + сервіс).
- **Controller** — приймає HTTP-запити; **Service** — логіка; Nest сам «вставляє» сервіс у
  контролер через конструктор (**dependency injection**).
- **Guard / Pipe / Filter** — глобальні шари: ліміт запитів, перевірка даних, обробка помилок.

## 3. Мобільний застосунок (`apps/mobile/src`)

| Файл / папка          | Роль                                                                                |
| --------------------- | ----------------------------------------------------------------------------------- |
| `app/_layout.tsx`     | Корінь застосунку: провайдери (дані, мова, жести, тема) і навігація.                |
| `app/index.tsx`       | Головний екран — колода карток і кнопки «Бачив / Не бачив».                         |
| `app/about.tsx`       | «Про застосунок»: перемикач мови, атрибуція TMDB.                                   |
| `hooks/use-deck.ts`   | Логіка колоди: сторінки, поточна картка, підвантаження наперед.                     |
| `lib/api.ts`          | Запит до нашого API: тайм-аут, перевірка відповіді за контрактом, типи помилок.     |
| `lib/query-client.ts` | Налаштування TanStack Query (кеш і повтори запитів).                                |
| `components/`         | UI-компоненти: картка фільму, стек карток, кнопки, стани помилок.                   |
| `i18n/`               | Переклади (`uk.ts` — головний, `en.ts` — має ті самі ключі), визначення мови.       |
| `theme/`              | Дизайн-токени: кольори, відступи, шрифти — жодних «магічних» значень у компонентах. |

Маршрути — це файли в `app/` (Expo Router): `index.tsx` → `/`, `about.tsx` → `/about`.

## 4. Тести

- `apps/api/src/**/*.spec.ts` — юніт-тести поруч із кодом (схема env, мапер, кеш, TMDB-клієнт).
- `apps/api/test/*.e2e-spec.ts` — тести всього застосунку через HTTP, з **фейковим TMDB-сервером**:
  контракт, атаки на вхідні дані, ліміти, кеш, падіння TMDB, перевірка, що токен ніколи не
  потрапляє в логи.

Запуск усього: `pnpm check`.

## 5. Захист від помилок у самому репозиторії

- `.githooks/pre-commit` — не дає закомітити `.env` і сканує зміни на секрети.
- `.github/workflows/ci.yml` — те саме + тести й аудит залежностей на кожен push.
- `pnpm-workspace.yaml` — правила безпеки для npm-пакетів (з коментарями, чому так).
- `.claude/` — правила для AI-інструментів: заборона читати `.env`.
