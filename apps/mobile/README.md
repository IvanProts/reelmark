# Reelmark mobile app

The Reelmark client for iOS and Android, built with Expo SDK 57, React Native 0.86 and Expo
Router. You sort movies by swiping cards (seen, not seen, want to watch), and the app builds your
library from those decisions. It works in Ukrainian and English, with no sign-up: the first
launch creates an anonymous account.

## Screens

| Route           | File                         | Purpose                                                           |
| --------------- | ---------------------------- | ----------------------------------------------------------------- |
| `/`             | `src/app/(tabs)/index.tsx`   | Deck tab: swipe cards, or use the buttons below them              |
| `/library`      | `src/app/(tabs)/library.tsx` | Library tab: "Seen" and "Want" poster grids, infinite scroll      |
| `/movie/:id`    | `src/app/movie/[id].tsx`     | Movie sheet: trailer, scores, story, where to watch, the decision |
| `/trailer/:key` | `src/app/trailer/[key].tsx`  | Full-screen YouTube trailer player                                |
| `/about`        | `src/app/about.tsx`          | Sheet: language, TMDB attribution, deleting your data             |
| other           | `src/app/+not-found.tsx`     | Sends unknown deep links to the deck                              |

Deep links use the `reelmark://` scheme (e.g. `reelmark://movie/603`); a sheet opened from a
link sits over the tabs, so closing it lands on the deck.

**Deck.** Swipe right for "seen", left for "not seen", up for "want". A stamp fades in and a
haptic tick marks the threshold; a short flick also counts. After "seen", a "Liked it?" 👍 / 👎
prompt stays for about 4 seconds; ignoring it is fine. Undo brings the last card back and deletes
its saved decision. Decisions are optimistic: the card leaves at once, and comes back with a
notice if saving still fails after retries. Tapping a card (it carries a "Details" chip) opens the
movie sheet. Screen-reader users get the three decisions as accessibility actions on the card, and
activating it opens the sheet; with Reduce Motion the card fades instead of flying and tilting.

**Movie sheet.** Everything needed to decide, from `GET /movies/:id/details` for any movie id
(so deep links work without the card on screen), cached per movie, language and region:

- header: poster, title, year · runtime · age rating, genres;
- ▶ Trailer (hidden when the movie has none);
- scores, each labelled with its source and read out with it: TMDB audience, Rotten Tomatoes,
  Metacritic (unknown scores are left out);
- tagline, overview, directors and top cast;
- where to watch in the device's region (`expo-localization`, validated with `RegionSchema`,
  else `DEFAULT_REGION`): stream / rent / buy rows of provider logos labelled with the provider
  name, the "Data: JustWatch" credit, and TMDB's where-to-watch page opened in the browser;
- the decision. Opened from the deck, Seen / Not seen / Want act on the top card exactly like the
  deck buttons (same animation, save, undo and "Liked it?" prompt; `src/lib/deck-bridge.ts`) and
  close the sheet. Opened from the library or a link, the decision can be changed or removed;
  for a movie with no known decision, picking one saves it.

**Trailer player.** A full-screen modal with `react-native-webview` around YouTube's
privacy-enhanced embed (`src/lib/youtube.ts`). The close button and "Open in YouTube" sit
outside the 16:9 video rectangle (at least 200×200 pt), never over it, and nothing autoplays.

## Getting started

From the repository root:

```sh
pnpm install
cp apps/mobile/.env.example apps/mobile/.env   # set EXPO_PUBLIC_API_URL, see below
pnpm dev:api                                    # in one terminal
pnpm dev:mobile                                 # in another; press i (iOS) or a (Android)
```

`pnpm dev:mobile` builds `@reelmark/shared` first, then starts the Expo dev server. The app runs
in Expo Go (which includes `react-native-webview`); no native project is checked in (`ios/` and `android/` are generated by
`npx expo prebuild` when needed).

## Configuration

The app has a single setting, `EXPO_PUBLIC_API_URL`, in `apps/mobile/.env`. Every
`EXPO_PUBLIC_*` variable is compiled into the app bundle and is readable by anyone, so it must
never hold a secret. Restart the dev server after changing it.

| Target           | `EXPO_PUBLIC_API_URL`                | Notes                                                    |
| ---------------- | ------------------------------------ | -------------------------------------------------------- |
| iOS Simulator    | `http://localhost:3000`              | The simulator shares the Mac's network.                  |
| Android emulator | `http://10.0.2.2:3000`               | `10.0.2.2` is the emulator's alias for the host machine. |
| Physical device  | `http://<your-computer-LAN-IP>:3000` | Same Wi-Fi network; start the API with `HOST=0.0.0.0`.   |
| Release build    | `https://…`                          | Release builds refuse plain `http` (`src/lib/http.ts`).  |

## Sessions

The app holds no secrets and no password. On first launch it calls `POST /auth/anonymous` and
gets two tokens:

- the **access token** (15 minutes) stays in memory only and goes in `Authorization: Bearer`;
- the **refresh token** (60 days, single-use) is stored with `expo-secure-store` (Keychain /
  Keystore, this device only).

`src/lib/session.ts` signs every request. When the API answers 401, it refreshes once and
retries; concurrent requests share that single refresh, because the server rotates the refresh
token on every use. If the server rejects the refresh token, the session is gone: the app starts
a new anonymous account and drops cached data. Network errors never end a session. Deleting your
data (About) calls `DELETE /me`, wipes secure storage and the query cache, and starts fresh.

The language picked in About is saved to the account (`PATCH /me`) and restored on the next
launch from `GET /me`; until then the app follows the device language.

## Trailer player security

The WebView shows third-party content, so it is locked down:

- **Source.** The app builds a one-iframe HTML page itself from the trailer key, which must match
  `^[A-Za-z0-9_-]{11}$` (the contract's `TrailerSchema`, checked again on the route param). The
  iframe loads `https://www.youtube-nocookie.com/embed/<key>?playsinline=1&rel=0`. The page's
  Content-Security-Policy lets it frame only that host and run no script of its own.
- **Referer.** YouTube refuses embeds in native WebViews that don't identify the app ("Error
  153"). The page is loaded with `baseUrl: 'https://com.ivanprots.reelmark/'` (the app id, equal
  to `ios.bundleIdentifier` / `android.package` in `app.json`) and
  `<meta name="referrer" content="strict-origin-when-cross-origin">`, so the embed request carries
  that origin as its Referer. Nothing is ever fetched from the base URL.
- **Navigation.** `onShouldStartLoadWithRequest` allows only `about:blank`, the base URL and
  `www.youtube-nocookie.com/embed/…`. A YouTube link the viewer follows in the main frame
  (`youtube.com`, `www.`/`m.youtube.com`, `youtu.be`) opens in the YouTube app or the browser via
  `Linking`; everything else (ads, trackers, other sites, app schemes) is blocked.
  `originWhitelist={['*']}` makes every URL reach that check, because the library would otherwise
  hand unlisted schemes to the OS itself.
- **Isolation.** No `onMessage` bridge, no injected JavaScript, `setSupportMultipleWindows={false}`,
  no scripted pop-ups, no link previews, and an incognito (non-persistent) data store.
- **Playback.** `allowsInlineMediaPlayback` with `playsinline=1`; fullscreen is the system
  player's.

## Project structure

```
src/
  app/          Routes (Expo Router): every file is a screen, _layout.tsx sets up providers
  components/   UI building blocks: MovieCard, CardStack, buttons, skeleton, status card
  hooks/        Data hooks: useDeck, useLibrary, useMovieDetails, decision mutations, profile
  i18n/         Dictionaries (uk.ts, en.ts), I18nProvider / useI18n, device language detection
  lib/          http.ts (requests, typed errors), session.ts (tokens), api.ts (endpoints),
                TanStack Query client, youtube.ts (player page and navigation policy),
                region.ts, deck-bridge.ts, haptics, formatting
  theme/        Design tokens: colours, spacing, radii, sizes, typography
assets/images/  App icon and Android adaptive icon layers
```

Conventions:

- Components use tokens from `@/theme`, never hard-coded colours or sizes, and render text
  through `AppText`.
- Every user-visible string, accessibility labels included, comes from `t('key')`.
- API responses are validated against the zod schemas in `@reelmark/shared` before use.

## Internationalisation

- `src/i18n/uk.ts` is the source of truth for keys; `en.ts` must contain exactly the same keys,
  which TypeScript enforces.
- `const { t, locale, setLocale } = useI18n()` gives any component the current language.
  `t('deck.counter', { count: 3 })` fills `{placeholders}`; a missing or unknown placeholder is a
  compile error.
- The language is the one saved to the account, else the first supported language from the
  device settings (`expo-localization`), else English. Switching it in About reloads the deck
  and library in that language.
- Numbers are formatted per language with `Intl.NumberFormat` (`8,2` in Ukrainian, `8.2` in
  English).

### Adding a language

1. Add its code to `SUPPORTED_LOCALES` in `packages/shared` and its TMDB language tag in the API.
2. Copy `src/i18n/en.ts` to `src/i18n/<code>.ts` and translate it, including `language.name`
   (the language's name in itself).
3. Register the dictionary in `dictionaries` in `src/i18n/i18n-provider.tsx`.
4. Add the code to `ios.infoPlist.CFBundleLocalizations` in `app.json`.

TypeScript reports any key that is missing from the new dictionary.
